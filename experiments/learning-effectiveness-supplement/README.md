# 100×10报告的独立评估补充

本目录复核既有 `learning-effectiveness` 实验证据，并补充用户指定的Obsidian笔记。原100×10实验代码、模型、日志和打包文件保持原样。

原实验已完成36个固定策略评估任务、1080条实际执行序列，每条10步，评估种子10000–10029。uniform三个训练种子的bank完全重复，每电路只提供30条独立随机基线；合并这些重复bank后，相当于900个评估组合。

第100轮主比较：int2float相对初始化/随机平均少0.100/0.078 LUT；i2c平均少0.911/1.289 LUT，种子1退化；max相对初始化可行率不变，相对随机高2.222个百分点。六个探索性主区间都包含零，三个电路均未验证稳定收益。

在仓库根目录运行只读证据复核和12条独立目录中的抽样重放：

```bash
.tools/conda-env/bin/python -B -u experiments/learning-effectiveness-supplement/validate.py --replay
```

不加 `--replay` 时仅重算原始日志和统计、校验模型/交付物/CEC/证据包哈希。抽样重放只写入 `results/learning-effectiveness-supplement/`，验证权重、检查点和全局Torch RNG不变。12条重放不是整批实验重复。

`validation.json`记录本次通过的核对，`recomputed-summary.json`保存重算数值。原清单中的根README因后续实验扩展已更新，该文件的原始哈希绑定到Git历史；其余37份交付文件及135份模型/探针当前哈希一致。原CEC的2217份网表与通过日志、证据包内10687份文件均已核对。

`original-note.md`是用户报告修改前的完整备份，`学习有效性实验.md`是补充后的报告。两张SVG保留原图内容，采用100x10专用文件名，避免与其他实验图混淆。

`build_note.py`在仓库内生成可审阅报告和文件哈希清单；`publish_note.py`仅将已核对的报告及两张图复制到清单指定目录，拒绝覆盖准备后发生变化的原文。Obsidian目录的写入需要该目录的文件权限。`published-manifest.json`仅在复制并逐一验证哈希成功后生成。

本次统计解释风险核对11/11，独立训练单位仍只有3个种子，评估仍限于训练电路。100×10使用10步评估，200×5使用5步评估且种子集合不同，不直接以绝对均值差异判断训练设置优劣。

提交时同步了用户精简后的最新Obsidian笔记，保存为`Obsidian-学习有效性实验.md`；`学习有效性实验.md`保留完整报告，`note-snapshot.json`记录两份文件的哈希与来源。

`max-lut-addition-20260928/means.json`记录max全部序列的可行优先选优LUT均值：初始化789.556、第50轮789.156、第100轮788.422、uniform790.267。该均值包含不可行候选，仅作辅助描述。该目录还保留加表格行之前及之后的报告与发布清单。
